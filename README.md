# WheelLog для iPhone

Нативное приложение на SwiftUI для моноколёс с Bluetooth LE. Оно распознаёт протокол по имени и сервисам Bluetooth. При неоднозначном результате выберите семейство в «Колесо → Протокол Bluetooth», запустите поиск и подключитесь снова.

## Поддержка колёс

| Семейство | Телеметрия |
| --- | --- |
| Begode / Gotway, Extreme Bull | Классические и новые варианты протокола, в том числе запись с Extreme Bull Rocket |
| KingSong | Протокол KingSong с показаниями ШИМ и температуры мотора там, где колесо их передаёт |
| InMotion / Solowheel | Протоколы V1 и V2. В тестах воспроизводятся записи V8S и P6 |
| LeaperKim / Veteran | Sherman, Abrams, Sherman S, Sherman Max, Patton, Lynx, Sherman L, Patton S, Oryx и Lynx S |
| NOSFET | Apex, Aero и Aeon по коду модели в телеметрии |
| Ninebot | Классический протокол One / Mini и отдельный протокол Z |

Список описывает семейства протоколов. Тесты воспроизводят BLE-записи выбранных моделей, а совместимость зависит от модели и прошивки. Для Sherman S сохранён отдельный декодер с тестом прошивки `003.0.15`. Фара и режим педалей доступны там, где приложение поддерживает соответствующие команды. Стробоскоп с регулируемой частотой доступен на Sherman S.

## Что есть в проекте

- **Приборы.** Главный экран использует классическую панель Android WheelLog 3.2.9. Свайп открывает параметры колеса, поездки и журнал событий. При потере связи над приборами появляется красное предупреждение, последние показания и максимумы остаются на экране. В параметрах знак ≈ отмечает заряд по напряжению, расчётный ток батареи и расчётную мощность.
- **GPS-маршрут.** Кнопка карты на приборах запускает запись маршрута и телеметрии колеса с общей шкалой времени. iPhone записывает координаты, скорость GPS, высоту и накопленный набор высоты в метрах. Неточные измерения высоты отбрасываются, оставшиеся сглаживаются перед подсчётом набора. В «Поездки → Маршруты» можно открыть запись, перемещаться по шкале времени и экспортировать маршрут с телеметрией в CSV. GPS продолжает запись во время разрыва BLE, для таких интервалов телеметрия колеса в маршруте отсутствует. Для фоновой записи запустите маршрут при открытом приложении и разрешите точную геопозицию.
- **Подложка карты.** По умолчанию используются Apple Карты. В «GPS-маршрут → Настройки карты» можно включить Яндекс Карты с собственным ключом Tiles API. Для показа положения транспорта в реальном времени сверяйте применимость тарифа с условиями Яндекса. [Настройка Tiles API](https://yandex.ru/maps-api/docs/tiles-api/quickstart.html) · [Условия использования API](https://yandex.ru/legal/maps_api/ru/).
- **CSV.** Отдельная запись включается на экране приборов. CSV содержит время UTC, время от начала записи, источник и телеметрию с единицами в заголовках. Высота и набор высоты доступны при одновременной записи GPS-маршрута. При разрыве BLE-соединения файл закрывается и остаётся в архиве. При блокировке телефона запись продолжается, пока iOS доставляет Bluetooth-уведомления и сохраняет работу приложения.
- **Камера.** Кнопка слева от Bluetooth открывает заднюю камеру на весь экран с кнопками поверх кадра и записывает вертикальные MP4 в 1080p. Скорость, ШИМ, мощность и заряд по умолчанию видны в предпросмотре и в самом файле. Кнопка настроек камеры меняет состав показателей. Ролик можно посмотреть в поездках, отправить или сохранить в «Фото». Звук записывается при доступе к микрофону. При уходе в фон запись завершается.
- **Архив.** Маршруты, CSV и видео находятся на отдельных вкладках. Значок корзины удаляет выбранную запись из WheelLog после подтверждения.
- **Колесо.** Включение и выключение фары, стробоскоп на 0,5, 1 или 2 Гц, режим педалей на остановленном колесе, просмотр порога звукового сигнала и скорости подъёма педалей. Прошивка фары Sherman S принимает обычные команды включения и выключения, поэтому частота мигания зависит от задержки BLE. При остановке стробоскопа приложение отправляет последнюю выбранную команду, а если её ещё не было — включение постоянного света. Колесо не подтверждает физическое состояние фары. При потере связи фара может остаться в состоянии последней принятой команды.
- **Демо.** В настройках колеса можно включить имитацию телеметрии. Записи и кадры с такими показателями отмечены как демо. Режим доступен без моноколеса.

## Установка с Windows через SideStore

1. Поместите содержимое папки `WheelLog-iOS` в корень GitHub-репозитория. Файл `.github/workflows/build-ios.yml` должен попасть в основную ветку. Для сборки достаточно этой папки с исходниками.
2. Откройте в репозитории **Actions → Build WheelLog IPA → Run workflow**. GitHub запустит проверку протокола и соберёт приложение на сервере macOS. Apple Account на этапе сборки не используется. В приватном репозитории сборка расходует минуты GitHub Actions по вашему тарифу.
3. После успешного запуска скачайте артефакт **WheelLog-iOS** и извлеките из ZIP файл `WheelLog.ipa`. Сохраните IPA в приложении «Файлы» на iPhone.
4. Если SideStore удалён, установите его снова с Windows по официальной инструкции. Проверьте, что на iPhone включён **Режим разработчика**. На iPhone подключите LocalDevVPN, откройте **SideStore → My Apps → +** и выберите `WheelLog.ipa`. SideStore подпишет и установит приложение с вашим Apple Account.
5. С бесплатным Apple Account обновляйте подпись в SideStore до истечения семи дней. После установки откройте **Колесо → Найти Sherman S**.

[Запуск сборки на GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow) · [Установка SideStore](https://docs.sidestore.io/docs/installation/install.html) · [Срок подписи](https://docs.sidestore.io/docs/faq.html)

## Установка на iPhone 16 Plus через Xcode

1. На Mac с JDK 21 выполните `bash WheelCore/gradlew -p WheelCore linkReleaseFrameworkIosArm64`, затем откройте `WheelLog.xcodeproj`. Проект требует iOS 17 или новее. Для симулятора на Apple Silicon соберите `linkReleaseFrameworkIosSimulatorArm64`, на Intel — `linkReleaseFrameworkIosX64`.
2. В **Xcode → Settings → Apple Accounts** войдите в свой Apple Account. В настройках цели **WheelLog → Signing & Capabilities** включите **Automatically manage signing** и выберите свою **Team** или **Personal Team**. Если идентификатор пакета уже занят, укажите свой.
3. Подключите iPhone, подтвердите доверие к Mac и включите **Developer Mode**, если его потребует Xcode. Выберите iPhone в качестве устройства запуска и нажмите **Run**.
4. В приложении откройте **Колесо → Найти моноколесо** и выберите своё устройство. Если колесо занято, отключите его в другом приложении перед поиском.

[Руководство Apple по запуску на устройстве](https://developer.apple.com/documentation/xcode/building-and-running-an-app) · [Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)

## Проверка

Для проверки декодера на Mac без iPhone из каталога проекта выполните команды. Набор использует синтетические пакеты для `003.0.15` и проверяет фрагментацию, CRC, значения и байты команд.

```sh
test_bin="$(mktemp -d)/sherman-checks"
xcrun swiftc WheelLog/Telemetry.swift WheelLog/ShermanProtocol.swift WheelLog/RouteAscent.swift \
  Tests/ShermanProtocolChecks.swift -o "$test_bin"
"$test_bin"
```

Порядок проверки на iPhone и неподвижном Sherman S.

1. Подключите BLE и сравните показания и версию прошивки с колесом или приложением LeaperKim.
2. Проверьте включение и выключение фары, затем запуск и остановку стробоскопа. После сворачивания приложения проверьте, что фара вернулась в постоянный выбранный режим.
3. Измените режим педалей и проверьте, что ответ колеса совпадает с выбранным режимом.
4. Запишите короткий CSV и MP4. Откройте MP4 из архива и проверьте звук, ориентацию и обновление показателей в сохранённых кадрах. Проверьте экспорт обоих файлов.

5. Запишите поездку с подъёмом и спуском. Проверьте линию на карте, набор высоты, телеметрию по шкале времени и поля `altitude_m` и `elevation_gain_m` в CSV. Во время записи отключите колесо и проверьте, что GPS продолжает запись, а приборы показывают последние значения с предупреждением.

Проект разработан на Windows. GitHub Actions проверяет декодер и расчёт набора высоты и собирает IPA с Apple SDK. Для проверки датчиков и Bluetooth нужны iPhone и колесо.

## Источники протокола

- [euc_ble_library](https://github.com/Tritbool/euc_ble_library) (GPL-3.0), версия 0.1.3. Используются её протоколы и очередь опроса. [Исходные BLE-записи для тестов](https://github.com/Tritbool/euc_ble_library/tree/2300f85aa52e69a44bc2ee975de0c9708437775c/euc-ble-core/src/test/resources/ble_frames) воспроизводятся с помощью `bash WheelCore/gradlew -p WheelCore jvmTest`.

- [Адаптер Veteran в WheelLog для Android](https://github.com/Wheellog/Wheellog.Android/blob/master/app/src/main/java/com/cooper/wheellog/utils/VeteranAdapter.java) и [расчёт тока и мощности](https://github.com/Wheellog/Wheellog.Android/blob/master/app/src/main/java/com/cooper/wheellog/WheelData.java)
- [Описание BLE-протокола Veteran / LeaperKim](https://github.com/eried/eucplanet/blob/main/docs/protocols/veteran.md) и [сведения о командах фары Sherman S](https://loeuc.ru/en/docs/wheels)

Классическая панель использует шрифт, пиктограммы и геометрию шкалы из [WheelLog.Android 3.2.9](https://github.com/Wheellog/Wheellog.Android/tree/3.2.9). Условия распространения приведены в [LICENSE](LICENSE).

Логотип Яндекса используется для обозначения подложки карты по [правилам Tiles API](https://yandex.ru/maps-api/docs/tiles-api/index.html#ispolzovanie-logotipa-yandeksa).
